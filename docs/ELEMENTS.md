# Upstream elements

One row per element class in upstream CircuitJS1 at the pinned commit (see [UPSTREAM.md](UPSTREAM.md)).
Generated by `tools/recon/elements.py | tools/recon/elements_md.py`, then reviewed by hand. The survey is
regex based, so treat "Engine hooks" as a porting checklist, not as proof.

## How to read the table

- **Text dump type**: the first token of the element's line in the legacy text format. Single
  characters are stored as characters (`r`), others as numbers (`174`). The loader accepts both
  forms: a token starting with a digit is parsed as a number, so `82` and `R` are the same element
  (`CircuitLoader.readCircuit`). `-` means the element has dump type 0 and can only be saved in the
  XML format.
- **XML tag**: the element name in the XML format (`CircuitElm.getXmlDumpType()`). It is the dump
  type character when that is printable, otherwise the class name minus `Elm`, unless the class
  overrides it.
- **Linearity**: the return value of `nonLinear()`. Linear circuits are LU factored once per
  analysis; any nonlinear element forces re-stamping and iteration every timestep.
- **Engine hooks**: methods the class overrides (itself or through a parent other than
  `CircuitElm`). `int` getInternalNodeCount, `vs` getVoltageSourceCount, `si` startIteration,
  `ds` doStep, `sf` stepFinished, `cc` calculateCurrent, `setc` setCurrent, `cin`
  getCurrentIntoNode, `conn` getConnection, `gnd` hasGroundConnection, `wire` isWireEquivalent,
  `snv` setNodeVoltage, `exec` execute (chips).
- **Examples (txt/xml)**: how many of the 373 bundled example circuits
  (`src/com/lushprojects/circuitjs1/public/circuits/`) use the element's dump type in the text
  format and its tag in the XML format. Subclasses that share a dump type (for example every
  `R` rail variant) share the count.
- **Notes**: `abstract` base classes are ported with their subclasses. `not in menu` means the
  class name does not appear in `Menus.java`, so it is created through an alias or another path
  (for example `RingCounterElm` via `DecadeElm`, `CustomLogicElm` via `UserDefinedLogicElm`).
  `XML only` elements have no text dump type. `RNG` marks code that calls upstream's
  `java.util.Random` (see below).

## Tiers

- **Tier 1**: exactly the elements PLAN.md Phases 2 and 3 name, plus their base classes.
- **Tier 2**: the families PLAN.md Phase 8 names (logic, flip-flops, counters, 555, transformer,
  relay, ADC/DAC, sweep, noise), the shared bases they need, the graphic elements (text, box,
  line) that many examples contain, plus anything used in 5 or more bundled examples.
- **Tier 3**: everything else. Port in table order within a tier unless the Phase 8 pass-rate
  report says otherwise.

## Randomness

Upstream seeds `CirSim.random` with `new Random()` (`CirSim.java:215`), so it differs on every
load. Three places use it:

- `OpAmpElm.doStep` calls `getrand(4)` while deciding whether to clamp at the rails
  (`OpAmpElm.java:176-179`). This is in a tier-1 element and it is on the convergence path.
- `GateElm.doStep` calls `getrand(10)` to break oscillation after 50 flips (`GateElm.java:352`).
- `VoltageElm` noise waveform calls `random.nextDouble()` (`VoltageElm.java:165`). Only the noise
  waveform uses it, but every voltage source subclass inherits the code path.

`CirSim.getrand(x)` negates a negative `nextInt()`, which stays negative for `Integer.MIN_VALUE`,
so `q % x` can be negative (`CirSim.java:124-129`). A port must keep that quirk. The Phase 1
reference patch must seed this generator so golden runs are reproducible, and the TS engine needs
an exact `java.util.Random` (PLAN.md section 8).
