# 2026-10-23: Tidy potentiometers

Branch `claude/project-thread-nvuf2m`. Gady found that the pot's wiper arrow crowds the pins and
covers its two resistance values as it moves. Perun drew pots exactly as upstream does: both
values beside the arrow on the wiper's side (where the wiper's wire leaves), moving with it, and
the arrow running to the very ends of the body. Of three proposals (screenshots in the project
folder `pot-symbol/`), Gady picked "values on the far side plus a tidier arrow".

## Done

- `potView` (packages/elements/src/view/passive.ts), when the new `DrawContext.tidyPots` is on:
  - both values on the side away from the wiper, where no pin is: stacked either side of the
    body's centre on a vertical pot, side by side above or below on a horizontal one. R1 sits on
    point 1's half. They no longer move with the wiper.
  - fixed-width text (owner's rule): `potValueText`, one decimal, five places for the number and
    one for the prefix (`  5.5kΩ`, `545.0 Ω`), carrying 999.95 up to the next prefix.
  - a solid arrowhead with its tip on the zigzag's peaks (or the box's side for European
    resistors), so even a wiper one grid step out reads as an arrow.
  - the wiper travels 24 units instead of the body's full 32, stopping 4 short of each end.
    The current dots follow it.
- Options > "Tidy potentiometers" (setting `tidyPots`, `drawn`, on by default, remembered). Off
  draws exactly as before (upstream). Schematic export, the browser save thumbnails, and the
  Obsidian player's print/PDF all follow it; part previews draw the tidy arrow.
- Strings in all 16 languages (by Claude, not native-checked). New `pot` icon.
- Tests: `packages/render/src/pot.test.ts` (far side, values steady as the wiper moves, horizontal
  placement, arrow tip inside the body, upstream drawing when off).
- Drawing only: the file format and simulation are unchanged, so no deviation entry. CircuitJS
  opens the same files and draws them its own way.
